# Idea Brief and product form

Normalize intent before proposing features. Use `Unknown` rather than invented precision.

| Field | Capture |
|---|---|
| Target User | Primary role and identifiable segment; who benefits versus who installs/pays |
| Situation | Trigger, environment, frequency; one concrete recent example if available |
| Problem / JTBD | Job and friction, without assuming the requested solution is necessary |
| Current Alternative | Existing product, prompt, manual process, or doing nothing |
| Expected Outcome | Observable user result and quality/time criterion |
| Core Workflow | Current sequence plus tentative desired journey, explicitly a hypothesis |
| Required Capabilities | Likely model, tool, data, API and integration requirements; not a stack commitment |
| Constraints | Budget, platform, permissions, privacy, latency, data, maintenance |

Add evidence supplied, critical unknowns, and a tentative product-form recommendation with confidence. Attach source IDs for research claims; user claims are attributed to the user.

## Product form

| Form | Prefer when | Test the boundary |
|---|---|---|
| Skill | Expertise or repeatable method improves a bounded task | Could native chat plus a saved prompt already suffice? |
| Command / Workflow | Ordered steps call multiple methods with checkpoints | Which transitions really need ordering or human input? |
| Plugin | Related capabilities need installation/distribution and shared dependencies | Does bundling reduce setup/use friction? |
| MCP / Tool | Essential capability is external data or deterministic action | Is the missing piece execution/access rather than reasoning? |
| Agent | Goal requires autonomous planning, decisions, tools and iterative correction | Is a bounded workflow simpler and sufficiently reliable? |
| Combination | Instruction, orchestration and access each solve distinct friction | Explain each layer's job; avoid unnecessary layers |

The user's chosen form remains intent, not a proven requirement. Recommend a form without silently replacing their scope.

## Clarification

Ask 1–3 questions per round, choosing those whose answers would change a decision. Resolve primary user and job before optional pricing, names or branding. For “automatically organize meeting content”, distinguish extracting actions from supplied transcripts versus recording/transcribing, and identify who uses the output. Do not infer call recording authorization or prescribe a full meeting platform.

Proceed to search when user, situation and job are sufficiently bounded; keep other unknowns visible. If those three are unclear, use tentative search branches while asking, rather than choosing a hidden segment.
