# Idea Framing

## Scope and inputs
Use when the user needs to clarify who benefits, what triggers the work, what is hard today and what outcome matters. Accept natural language, observations, current workflows and constraints. A naming-only or implementation request does not imply full discovery.

## Tools
Start with user-provided material. Check current official platform documentation only if a capability affects the form decision. Ecosystem research belongs to ecosystem-scan.

## Method
1. Use the eight fields in the [brief template](../../references/idea-brief-template.md). Separate user evidence from assumptions; preserve `Unknown`.
2. Establish the job, current alternative and expected result before proposing a workflow or capabilities. Treat the desired journey as a hypothesis.
3. Ask 1–3 high-information questions per round when answers would change the decision. Prioritize primary user, concrete trigger and JTBD. Continue independent material preparation while waiting.
4. Assess Skill, Command/Workflow, Plugin, MCP/Tool, Agent or Combination. Explain each layer's purpose and confidence; the word “Agent” is not proof that autonomy is needed.
5. Handoff to search once user, situation and job are bounded. Other unknowns need not be resolved prematurely.

## Deliverable
An **Idea Brief** with eight fields, evidence, critical unknowns, tentative form, rationale and confidence. Follow `idea_brief` in the [contracts](../../references/io-contracts.md).

End with knowns, critical unknowns and next action. Deliver the current brief before asking questions. Do not score competitors, manufacture certainty or issue a build decision at this stage.
