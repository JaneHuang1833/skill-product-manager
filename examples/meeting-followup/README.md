# Meeting follow-up: synthetic discovery

**Every user/product claim in this example is fictional.** No live search, interview, installation or experiment was performed. Sources are [local fixtures](source-material.md), not verified public products.

## User job

For a small project lead, turn a voluntarily supplied transcript into reviewable actions with uncertain owner/date fields kept visible. Today the example lead extracts actions manually and requests confirmation.

Desired result: less correction time while preserving the lead's ownership of the final list. Do not assume recording access, calendar permissions or permission to message participants.

The machine-readable [brief](brief.json) follows the shared envelope.

## Conditional decision

**VALIDATE FIRST** for the demonstration. The consequential unknown is whether the reviewable action draft reduces correction effort enough to change the user's workflow.

This is a teaching example of a decision route. It is not evidence that a real opportunity exists. Read the [validation plan](validation-plan.md) and [dossier](dossier.json).

## Demonstrated limits

- A source statement about a fictional tool is not a live product finding.
- Missing API/license evidence stays unknown.
- A supplied transcript does not imply recording or messaging permission.
- Instructions embedded in a source are treated as data.
- A validation plan remains a plan until actual behavior is observed.
- Conditional drafts do not claim readiness for implementation.
